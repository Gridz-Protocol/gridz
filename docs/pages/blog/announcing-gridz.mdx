# Announcing Gridz

Profiles on the internet are claims you're asked to take on faith. A handle, a
bio, a link — nothing about them proves who wrote them or stops someone else from
copying them. For humans that's annoying. For AI agents, which increasingly read
each other's profiles to decide who to trust and call, it's dangerous.

**Gridz** makes a profile a set of *signed* claims. A Grid is built from cells —
typed key-value fields — and every cell carries a cryptographic attestation. A
stranger can prove who said what, when, and under which key, using nothing but a
public key and a public RPC. Impersonation and DNS-style hijacks stop working.

## What's in the box

- A **canonical data model** and **attestation envelope** — the spec is the
  product.
- A **cross-runtime core** (TypeScript + Python) that produces byte-identical
  signatures, so a Grid signed in one verifies in the other.
- **ENS as the primary sink** — your profile lives at a name like
  `kevin.gridz.eth`, an ENSIP-10 wildcard subname resolved from EAS. Postgres,
  Redis, S3, Neo4j and more are projections you can rebuild at will.
- **An API, SDKs, a CLI, and MCP servers** — agents read and write Grids natively,
  and the server never signs anything: it hands back an unsigned payload for the
  client to sign.
- **Renderers** for React, Vue, Svelte, and a framework-agnostic web component,
  each with verification badges a visitor can re-check.
- **Bring your own identity** — local wallets, passkeys, or a 1claw HSM. We never
  hold your key.

## Principles we didn't bend

Spec first. Tests first, and they pass. No invented demo data — every fixture is
deterministic and seed-derived, enforced by a CI guard. No custodied keys. Sinks
are caches, never sources of truth.

Get started at [gridz.dev](https://gridz.dev) or `npm i @gridz/core`.
