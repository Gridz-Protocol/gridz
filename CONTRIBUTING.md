# Contributing to Gridz

Thanks for helping build Gridz. A few principles keep the project coherent:

## Ground rules

- **Spec first.** The JSON Schemas and EIP-712 types in `specs/` are the source of
  truth. Change them before changing code that implements them; the drift tests
  will hold you to it.
- **Tests are the gate.** Write tests as you write code. A change is not done
  until `pnpm -w run check` (lint + typecheck + test + build), `uv run pytest` in
  each Python package, and `pnpm -w run check:nomock` all pass. Coverage
  thresholds are enforced — don't lower them; add tests.
- **No invented data.** Never commit example users, fake bios, or placeholder
  profiles. Fixtures are deterministic and seed-derived, and live under
  `__fixtures__/` or `test/`. The `check:nomock` CI guard enforces this.
- **No custodied keys.** Gridz never holds a private key. New signers wrap an
  external capability (local wallet, passkey, HSM).
- **Skip, don't fake.** Tests needing a network resource (testnet, a database, a
  1claw account) skip with instructions when it's absent — they never mock it
  silently.

## Workflow

```bash
pnpm install
pnpm -w run check          # TS: lint + typecheck + test + build
pnpm -w run check:nomock   # no-mock-data guard
# Python lanes:
cd python/gridz && uv sync --extra dev && uv run pytest
# Contracts:
cd contracts && forge install foundry-rs/forge-std --no-git && forge test
```

## Changesets

User-facing changes need a changeset:

```bash
pnpm changeset
```

Pick the affected packages and a semver bump; describe the change for the
`CHANGELOG`. Release PRs are generated by the Changesets bot.

## Commits & PRs

- Keep the working tree green at every commit.
- Reference the spec section or BRIEF step you're addressing.
- One logical change per PR where possible.
